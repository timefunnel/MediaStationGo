# 已迁移云盘图片的旧地址兼容

图片引用迁移到 TMDB、其他外部图源或永久本地图后，客户端仍可能保留
`/api/img/cloud/:type?ref=...` 或 `/api/cloud/play/:type?ref=...`。
仅修改媒体记录不能使这些旧地址停止访问云盘；尺寸变体的读取也仍依赖原图文件存在。

`cloud_artwork_aliases` 将旧地址关联到媒体记录及其 `poster_url` 或
`backdrop_url` 字段。图片 URL 只保存在媒体记录中，修改当前图片后旧地址随之生效。
关联表不保存云盘路径、签名直链或替代图片 URL。

## 请求处理

1. 在旧云盘缓存和云盘解析之前，使用解码后的 `provider + ":" + ref`
   的 SHA-256 查找关联；provider 和 ref 按 `CloudArtworkSourceHash` 去除首尾空白。
2. 已关联的请求读取当前有效媒体记录的指定图片字段，再交给现有 ImageProxy。
   原请求的宽度、高度、质量参数和 GET/HEAD 方法保持不变。
3. TMDB 的可直连宽度请求继续返回 CDN 302；高度限制及本地图等继续使用现有缩放链路。
4. 已关联但媒体被删除、图片字段为空时返回 410；查询失败或目标仍为云盘图片时
   返回错误。这些请求不会读取旧云盘缓存或再次调用云盘解析。
5. 未关联的图片维持现有云盘处理流程，视频请求不查图片关联表。

## 迁移数据

应用启动时通过 `model.AllModels()` 创建关联表；建表不会自动导入历史映射。
历史关联必须从经过核验的图片迁移备份建立，并在正式发布时单独导入：

- 同一个旧 provider/ref 的所有替代图片必须一致；有冲突时停止导入。
- 选择仍有效、当前图片与迁移结果一致的媒体记录和图片字段作为关联目标。
  同一图片有多个持有记录时，优先使用海报字段，再按媒体 ID 固定选择。
- 导入前再次校验目标媒体未删除、图片字段未变，并备份已有的关联记录。
- 在数据库事务中插入关联；已有 SourceHash 若指向不同媒体或字段，必须停止，不能覆盖。
- 使用 source_hash、media_id、image_field 和创建时间持久化，不复制图片 URL。
- 正式验证旧入口的尺寸请求时，必须确保不会因映射遗漏而调用真实云盘。
  未得到专门授权，不运行旧云盘图片批量探针。

本修复不删除现有原图和变体缓存。来源尚未归属的变体不能直接认定为废弃文件；
缓存清理是独立操作，需在旧地址兼容已发布并验证后确定范围。
