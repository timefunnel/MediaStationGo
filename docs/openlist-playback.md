# OpenList 视频直链播放

MSG 使用已入库播放地址中的 OpenList 完整文件路径调用 `POST /api/fs/link`，读取返回的 `data.url`。此接口需要 OpenList 管理员 Token 或管理员账号；普通账号会收到明确的权限错误。Token 由 MSG 的存储配置服务加密保存，不应写进仓库。

`/api/fs/link` 省去 `/api/fs/get` 的重复文件查询和关联目录列表。取链不依赖码率、时长、音视频轨道等媒体探测结果，也不需要重新扫描媒体库。

签发请求透传播放客户端的 User-Agent。返回头中仅与客户端一致的 User-Agent 可以直接用于 302；其他必需头或不一致的 User-Agent 会明确报错，不能通过 302 携带，也不会切换到 WebDAV 或代理播放。

现有按文件路径和 UA 缓存、并发合并、超时、失败冷却及限流保护继续生效。正常取链只调用一次 `/api/fs/link`。原有仅针对 `430004` 文件对象缓存缺失的精确父目录恢复逻辑保持不变；不会预先列目录或设置 `refresh=true`。

本地回归使用模拟 OpenList/CDN，不访问真实 115。真实链路验证需单独限定请求次数、并发、时间与重试范围。
