# 第二账号补齐：按库启动与独立节点

2026-10-27，本地实现。尚未部署或联调真实账号。

## 用户操作

维护 B 账号的登录授权，在「系统任务 → 文件信息队列」保存媒体库选择，打开「第二账号自动补齐」预览范围及总预算，然后启动。空选择覆盖全部云端库。无需准备来源分享、目录 ID、JSON 或逐批执行命令。运行中可以停止。

程序自动完成：读取 MSG 固定快照 → 匹配已有入库库根 → A 核验身份并创建库根分享 → B 创建本任务专用暂存目录 → 每批 10 项自动转存、校验、复用/共享查询/必要的 probe → MSG 校验并回填 → 下一批。完整信息不会因版本旧而单独排入任务。

普通用户无需维护节点连接参数。以下配置由部署管理员完成。B 授权更新只替换节点的私密凭据文件，不复制 A 凭据，不在聊天、Git、命令参数或日志中传递凭据。首次登录仍需账号持有人完成官方授权；本实现没有新增扫码轮询。

## 管理员部署

复用当前镜像中的 `media-probe-worker`，在独立节点启动私有服务：

```text
media-probe-worker serve -listen 127.0.0.1:8786 -credentials /private/115-b.json -state-dir /private/probe-state -ffprobe /usr/bin/ffprobe
```

节点从环境变量 `MEDIA_PROBE_NODE_TOKEN` 读取至少 32 字符的服务密钥。默认仅监听回环；跨主机应通过 HTTPS 代理连接，或走已有私网。反向代理的上游读写超时须覆盖 16 分钟，禁止自动重试 POST，且不要记录请求体和 Authorization。镜像运行时须覆盖默认 entrypoint，并禁用针对 MSG Web 服务的原 healthcheck。一个状态目录只运行一个实例；异常退出保留锁，核对旧进程后由管理员处理。节点启动前检查 B 私密文件和本地 ffprobe 可执行路径。

MSG 配置 `media_probe_worker.url`、`media_probe_worker.token`，对应环境变量 `MEDIASTATION_MEDIA_PROBE_WORKER_URL`、`MEDIASTATION_MEDIA_PROBE_WORKER_TOKEN`。远程公网 URL 必须使用 HTTPS；HTTP 仅允许回环或私网 IP。MSG 使用现有 `resource_import.pipeline_url/token` 访问 media-pipeline 的鉴权接口 `GET /v1/media-probe/roots`。该接口只返回现有库根配置，不列目录、不刷新 OpenList、不访问 115。两个服务须同时升级；缺接口或库根 ID/路径不一致时明确失败，不自动搜索云盘修补配置。

B 凭据沿用 worker 私密文件格式：`user_id`、`access_token`、`refresh_token`、`expires_at`、`cookie`。Cookie 和 Token 必须属于同一 B。账号 A 来自 MSG 已有 `cloud115` 配置，A、B 不允许相同。B Token 即将到期时每批最多刷新一次，刷新计入控制预算，鉴权错误不刷新重试。B 不得与其他服务并行刷新同一授权。

## 固定范围与预算

A 初始化沿用已有 StorageConfigService 的网络出口/代理设置，不把 A 凭据交给独立节点，也不为 A 自动切换出口。B 控制与媒体读取继续使用独立节点的固定直连出口。

预览只访问 MSG 数据库、pipeline 配置及 B 节点本地状态，真实 115 请求为 0。每任务最多 5 个库根。设缺口文件数为 N、库根数为 R、批数 K=ceil(N/10)：

- A 最多 R+1 次请求：身份核验一次，`webapi.115.com/share/send` 每库根一次。
- B 初始化最多 3 次控制请求（当前身份核验和建目录共 2 次）。
- 每批控制最多 80 次、共享查询最多 1 次、媒体读取最多 60 次/320 MiB 响应体，单文件最多 6 次/32 MiB，最长 900 秒。
- 整任务控制总上限 R+4+80K 次，媒体读取最多 60K 次/320K MiB，共享服务最多 K 次；最长 180+910K 秒。
- 固定并发 1；控制请求间隔至少 5 秒、媒体请求至少 1 秒、文件/批次之间至少 10 秒。不触发 OpenList refresh，不自动重试，不自动提高预算。

界面展示整个有限任务的范围和预算，一次确认覆盖各批，不需要逐批确认。实际 115/CDN 执行仍受项目许可规则约束，存在限流、封禁、账号关联、容量及链路失败风险；账号隔离不能量化风险降幅。

## 持久化与故障行为

完整清单只传 B 节点一次，后续批次引用清单 ID 和摘要。节点 API 使用服务密钥，只接受固定来源、默认预算和本任务创建的 B 父目录；不接收任意程序、上游地址或文件路径。签名直链仍只在内存。节点用上一批已验证内容缓存减少重复探测。

MSG 的任务检查点使用已有 CryptoService 加密；公开状态不含 Cookie、Token、分享链接或口令。任务表只存编排进度，`media` 仍是技术信息的唯一业务来源。B 节点清单、批次与检查点需保留在 0700 私密目录，文件 0600；Windows 由部署管理员设置相应 ACL。

主账号文件信息队列与独立补齐任务互斥；正常播放仍可以补齐，导入时继续核对逐媒体锁和快照指纹。路径、文件大小、已有字段、映射或结果范围冲突时停止，不覆盖冲突字段。原文件执行期间应保持稳定；同路径同大小的云端替换而 MSG 尚未同步，不能只靠离线快照实时发现。

每批回填持久化后才进入下一批。已完成批次重复提交只返回保存的结果，不再次转存。创建/转存结果不明、节点断线、超预算或服务重启时停止并保留检查点，不后台重放。停止后可重新选择范围生成新任务，已补齐记录跳过；对状态不明的旧操作不自动重新提交，管理员可读取检查点诊断。

B 副本和 A 来源分享默认保留，不实施自动删除或取消分享。节点磁盘或 B 容量不足时停止。本轮未验证真实账号、分享响应、转存配额、CDN 或真实 ffprobe 链路；本地测试使用本机 HTTP 模拟服务及模拟 probe。

创建分享协议参考 [p115client 源码](https://github.com/ChenyangGao/p115client/blob/main/p115client/client.py)，复用本项目已有分享清单/转存协议，不引入新的 SDK 依赖。
